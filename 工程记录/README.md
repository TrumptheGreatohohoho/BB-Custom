# 工程记录（记忆区 + 施工区）

本目录是**易变工作记忆**区：记录"这台机器现在是什么状态、这次做了什么、还有什么没验证、
发现了什么新问题"。它和 `docs/` 的分工是刻意分开的。

## 与 `docs/` 的分工

| 区域 | 性质 | 内容 | 更新方式 |
| --- | --- | --- | --- |
| `docs/` | 长期稳定工程记忆 | 入口规则、架构契约、序列化设计、开发手册、追加式工程日志 | 谨慎、结构化、跨机器长期有效 |
| `工程记录/` | 易变工作记忆 | 本机实测快照、每次会话的施工记录、待办汇总、具体缺陷档案 | 高频、追加式、允许过期 |

规则：

- **不复制** `docs/` 里的稳定契约和设计说明，只链接过去（如 `../docs/current-state.md`）。
- `docs/` 记录"设计上是什么"，本目录记录"这台机器上实际测到了什么"。
- 结论必须带证据：命令、文件路径、大小、SHA-256、日志行、时间戳。
- 区分**实测**与**文档声称**：文档说 A 而实测是 B 时，两边都写下来，不要默默改文档。
- `当前状态.md` 是活文档，可整篇覆盖更新；施工记录和问题档案按日期追加，不删旧条目。

## 索引

| 文件 | 作用 | 何时更新 |
| --- | --- | --- |
| `当前状态.md` | 本机环境、git、构建/Steam 一致性、备份基线、最近会话事实 | 每次核对本机状态后覆盖更新 |
| `待办与回归清单.md` | 汇总所有"待人工游戏内回归"项和已知问题 | 验证一项就勾掉一项；发现新问题就追加 |
| `施工记录/YYYY-MM-DD.md` | 每次会话做了什么、发现什么、边界在哪 | 每次工作结束新建/追加 |
| `问题记录/*.md` | 单个缺陷的现象→证据→根因→影响→修复→验证 | 发现新缺陷时新建 |
| `验收记录/*.md` | 单个修复的**游戏内**验收判据、触发步骤与待填结果 | 部署后建立，人工验证后填写 |

## 本目录与 git

- 本目录**没有**被 `.gitignore` 排除，会随 `main` 同步到另一台电脑，这正是记忆区需要的。
- 但 `build/`、Steam 目录、存档、`.bbca-backup`、`.bbca-disabled` 都**不进**仓库，
  在本目录里只记录它们的哈希和清单。
- 遵守 `../docs/git-sync.md`：开始前 `git status` + `git pull --ff-only`，离开前 commit + push。

## 边界（与工程铁律一致）

本目录只写文件，不做部署。任何 Steam 写入仍然受 `../START-HERE.md` 第 6 节的铁律约束：
安装前必须关闭 `BattleBrothers.exe`，绝不删除/覆盖/修改任何 `.bbca-backup`。
