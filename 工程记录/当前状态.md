### ⚠️ 本机 git 联网注意事项（踩过的坑，值得记下来）

- 本机装了 **WestWorldVPN**，它把 **WinINET 系统代理**设成 `http://127.0.0.1:21882`
  （另有 SOCKS5 在 `21881`，进程 `wwss_privoxy` / `wwss_socks5`）。
  它的 `LetsTAP` / `ZTN Adapter` 两个虚拟网卡状态始终是 **Disconnected** —— 不建隧道，只做代理。
- **git 的 libcurl 不读 WinINET**，所以"浏览器能上、git 上不了"是正常的，不是 git 坏了。
- 更关键的是：**那两个本地代理本身对 git TLS 不可用**。实测
  `git -c http.proxy=http://127.0.0.1:21882` 与 `socks5h://127.0.0.1:21881` 都报
  `schannel: failed to receive handshake`；`Invoke-WebRequest -Proxy` 对这些站点一律超时。
- 但**直连是通的**。VPN 起来之后 `Test-NetConnection github.com -Port 443` 返回 `True`，
  且 `git -c http.proxy= ls-remote origin` 正常返回。
- ✅ **可用做法**：显式清空代理再推送 ——
  `git -c http.proxy= -c https.proxy= push`
  本轮即以此成功：`1c42cb5..23c2531  main -> main`。
- 若直连也失败，先 `Test-NetConnection github.com -Port 443` 确认是网络层问题，
  再按 `../docs/git-sync.md` 停下并报告，**不要** force push 或改用目录复制。
